## 处理决策

1. 准时交付率使用“实际交付日 ≤ 计划交付日”的明细行占比。
2. 运费只对可数值化的记录求和，并与 60.0% 覆盖率同时展示。
3. 运输方式缺失的 360 行标记为“未记录”，不丢弃。
4. 能耗数据按月、小时、负荷类型和工作日/周末汇总。
5. 没有可验证电价时，不把参数化电价情景表述为真实电费或已实现节省。

## 新增分析模块的质量控制

### 物流逐单复核队列

- 队列必须保留原始发运记录标识，确保每条待办能够回到来源行；项目生成的 `review_id` 仅用于队列标识。
- 高货值阈值为行货值全体 P95，长延期为至少30天，高已知运费为数值运费 P95；非数值运费状态也进入完整性复核队列。P1 为延期≥30天且同时高货值/高已知运费、延期≥60天或货值≥P99；P2 为其余单一高货值/延期/运费触发；P3 为仅运费完整性触发。保留全部触发代码与证据字段。`P1/P2/P3` 是复核优先级，不是风险损失金额。
- 数值运费与非数值状态分别计数、分别展示。空值、已含货值、另行开票、引用其他单据等状态不得填成 0，也不得汇入“已知运费”金额。
- 建议部门按触发类型路由：延期至物流/计划；非数值运费至物流/应付/数据治理；高运费至采购/物流；高货值至采购/供应商管理。实际使用时应按企业职责映射调整。
- 线路聚合维度为运输方式、目的国和制造地点。解读延期率时同时查看发运行数；小样本切片用于复核提示，不能推断因果或供应商过错。
- 后续可审计检查应验证队列去重、原始 ID 覆盖、触发条件重算、优先级映射、缺失运费状态与空数值一致性，以及线路切片对原始明细的行数/货值勾稽。

本次快照生成 **4,835** 条待办：P1 **202** 条、P2 **751** 条、P3 **3,882** 条；ID 唯一、都保留原始发运ID，运费完整性触发记录的数值运费为空且状态不为 `numeric_amount`。三维线路聚合共 **815** 个组合；新增测试核对线路汇总行数及已知运费金额与原始发运明细一致。优先级只代表待办排序。

### 能耗费用情景

- 能耗读数间隔为15分钟；平均功率近似按 `kW = interval_kWh × 4` 计算。需量费情景逐月取该近似功率最大值并按月份累计，属于简化模型，不是账单需量的核算替代。
- 分时段和费率是作品集模型参数：峰 09:00–16:59，平 07:00–08:59及17:00–21:59，谷 22:00–06:59；工作日与周末相同。若没有校准的数据时区、当地分时电价政策及计量时间边界，不能将其当成真实费率映射。
- 峰段转谷段的负荷转移必须守恒总 kWh；削峰只调整月最大需量假设，不额外降低总用电量。基准、轻度、强化情景的负荷转移/削峰比例分别为 0%/0%、5%/3%、10%/8%。
- 费率为可编辑假设，测算金额、情景差额和敏感性都标记为模型值。它们不是经电费账单验证的实际成本、节省或降本成效。
- 接入真实应用前，需要用当地账单与合同核对峰平谷时段、工作日历、需量单价、计量周期和最大需量取值方式；再由设备/生产数据确认转移和削峰在现场可行。

当前分时结构覆盖 **18** 个“工作日/周末 × 峰平谷 × 负荷类型”组合，35,040 条间隔用电观测均纳入汇总；另有12个月度峰值需量近似、3个成本情景和18个单参数敏感性组合。默认情景测算约为：基准 **997,311 元**、轻度优化 **971,820 元**、强化优化 **940,915 元**。这些数值是模型自检结果，不是实际电费数据；相关规则由新增分析测试覆盖。
